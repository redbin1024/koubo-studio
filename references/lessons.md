# 踩过的坑

按「会浪费你多少时间」排序。这些全部是实测撞出来的，不是猜的。

## 量片

1. **几何必须靠像素量，不能靠肉眼估网格。** 第一版按目测把信息卡做成 x 0.115–0.63，
   实际用填充色掩膜扫一遍才拿到真值 x 0.114–0.878 —— 宽度差 30%，条目文字直接顶到卡外。
   **先采样填充色，再用颜色掩膜求 bbox。**

2. **拿直方图桶底当参考色会整块漏掉。** 卡片实际是 `#A0A09F`，量化到 `#A09090` 后蓝通道
   差 15，容差 12 就一块都筛不出来。**先量化定位候选，再把桶内像素的真实中位色取回来重数一次。**

3. **纯黑/纯白帧会毁掉相对阈值。** 淡入淡出、闪白帧的「单色占比」恒为 1.0，
   按 `0.6 × 峰值` 取阈值会被顶到天上，真正的卡段一个都选不出来。按亮度先把这类帧排除。

4. **补洞之后才敢算矩形状。** 卡片上的文字和图标会打出很多洞，直接算「占 bbox 的比例」
   会得到 0.48 这种值，把真卡片否掉。从画框边界泛洪补洞，再算。

5. **画中画的判据不是拉普拉斯高频。** 卡片的粗体字拉普拉斯比人脸的还高。真正的判据是
   **粗尺度梯度**：卡段背景是「模糊放大的真人」，模糊把低频结构也抹掉了，所以粗尺度
   梯度接近 0；画中画没模糊，粗尺度梯度仍然很高。

6. **「面积最大 s.t. 均值 ≥ 阈值」对阈值极度敏感**（阈值差 1 就换一个答案）。
   改成两步：先用 **Kadane 找最密的核**（稳定），再从核往外长到真实外沿。
   往外长的判据是**新增那条边自己够不够密**，不是「加进去后整体均值还够不够」——
   后者会把旁边的空白背景甚至卡片一起吃进来。

7. **字幕检测要先把深色掩膜膨胀再和亮点求交。** 反过来对灰度图做 `MaxFilter`
   会把紧挨白字的黑边一起吞掉，永远查不到字。

## 渲染

8. **zsh 里 `$VAR[0]` 是数组下标，不是字符串拼接。** `fontsdir=$FONTS[v]` 被解析成
   「取数组 FONTS 的 v 元素」，滤镜图里少了一个 `[v]`，ffmpeg 报
   `Output with label 'v' does not exist`。**变量后紧跟方括号必须写 `${VAR}[v]`。**
   这个坑在 bash 下不出现 —— 本项目全部脚本改走 Python 生成命令，从根上绕开了。

9. **libass 的 `fontsdir` 不能指 `/System/Library/Fonts`**，中文会全变方框。
   指到用户字体目录（macOS 是 `~/Library/Fonts`）。

10. **PIL 渲染 Apple Color Emoji 只接受固定点阵尺寸。** `truetype(..., 164)` 直接抛
    `OSError: invalid pixel size`，160 正常。要别的尺寸必须先渲 160 再 resize。

11. **金色渐变字必须拆 glyph / ring 两张 mask**，且渐变覆盖整幅高度，否则字会被横向切掉。

12. **把慢操作挪出逐帧循环。** 整屏高斯模糊在 1080×1920×1113 帧里跑不动；
    改成 ffmpeg 先出 `work/blurred.mp4`，逐帧只读不算，整片合成 30s 跑完。

17. **macOS 的 libass 不认 `fontsdir`。** Homebrew 的 libass 0.17.5 只链了 CoreText
    provider（`nm -u` 里一个 `CTFontManagerRegisterFontsForURL` 都没有），
    `subtitles=...:fontsdir=` 是空操作 —— 字体没进系统就是整屏方框，设
    `ASS_FONTPROVIDER=fontconfig` 也没用（libass 根本没链 fontconfig）。
    要换字体只有两条路：装进 `~/Library/Fonts`，或者自己用 Pillow 画字幕
    （现在走的就是后者，见 `scripts/caption_layer.py`）。

18. **换字体必须重算字号，而重算的唯一正确姿势是「实测」。** 不同字体同字号下字身宽
    能差 20%+（得意黑 0.8em，常规黑体 1.0em），按「`max_width` / 最长行字数」估出来的
    字号只对估它时用的那款字体成立 —— 换个宽字身，长行当天就顶出画面。
    `caption_layer._fit_size()` 现在从 `size_cap` 往下实测到放得下为止，换字体不用再手算。

19. **卡面取字重不能跨族。** `make_assets.py` 原来写的是 `find_font("Bold")` /
    `find_font("Medium")` —— 这是**全局**按文件名找字重，工程 `fonts/` 里没有就直接落到
    系统目录，于是字幕用 A 家族、卡面标题用 B 家族、卡面副标用 C 家族凑在一张卡上，
    看着就是「没做完」。正确做法是 `match_font(family, "Bold")`：先在同族找字重，
    同族只有单一字重（如阿里妈妈数黑体只有 Bold）就整张卡面都用它。

20. **别拿程序化倾斜的斜体中文当字幕。** 中文没有真斜体，靠 `Oblique`/几何倾斜做出来的
    是歪笔画，1080 宽小屏上读起来就是「廉价综艺感」；而且斜体配厚描边会互相放大，
    字更容易糊成一团。要「有网感」优先选**正体粗黑**（阿里妈妈数黑体 / 优设标题黑一类），
    靠字重和留白撑，不靠歪。

21. **给剪映的草稿，`app_source` 必须是 `"lv"`，不能留 `"cc"`。** `capcut init` 的种子模板
    是 CapCut 国际版 6.5.0 的，产出的草稿带着 `{"app_source": "cc", "app_version": "6.5.0"}`。
    `app_source` 是**真实语义分支**（capcut-cli 自己就拿它区分遮罩字段名、取值范围），
    剪映据此走 CapCut 的特效/动画命名空间 —— 而草稿里的动画 id（弹入 1644313 之类）是
    **剪映命名空间**的，两边对不上，表现就是**字幕动画全部「加载失败」**。
    `scripts/make_jianying_draft.py` 的 `stamp_jianying_platform()` 每轮把标记改回
    `{"app_source": "lv", "os": "mac"}`。**故意不写 `app_version`**：capcut-cli 的写入护栏
    只要看到剪映 >= 6.0 的版本号就拒绝写入（`version.js` 的 known-broken 区间），而那个护栏
    同时就是「剪映正开着这份草稿就别写」的保护，比版本号本身值钱。另外 `capcut init`
    会从草稿库**最新的草稿继承标记**，库里留着一份带版本号的旧草稿，新草稿就会被一起拦。

## 交付

13. **参考片的「无片尾卡」里可能有一段快速淡黑。** 抽最后一帧是纯黑，但前 0.4s 还是正常
    画面 —— 它是快速淡出，不是黑场卡。照抄成 0.4s 淡黑，观感才对。

14. **粗剪的静音切割不认识「同一句录了三遍」。** 内容级去重是判断，不是算法，
    要人工决定保留哪一遍。`--merge-gap` 只解决碎切，不解决重复。
15. **手机外录的人声可能比参考片低 18 dB。** 实测一条素材人声只有 −32.9 LUFS
    （参考片是 −15.3 LUFS），而音效是按绝对电平铺的 —— 不先给粗剪的人声做一遍响度归一，
    音效会把人声整个盖住，成片还会被真峰顶住上不去。粗剪阶段做两遍法 loudnorm，目标 −16 LUFS。
16. **capcut 的 `add-video` 不要传 duration。** 传了会把素材时长写成「这一段的时长」，
    随后 `trim` 出的 in-point 就越界；剪映会把入点夹回 0，于是每个片段都从文件开头开始播
    （`capcut lint` 会报 `source-range-exceeds-material`）。让它自己 ffprobe 拿真实时长。
17. **剪映不会按画布宽度折行。** 字幕必须在写入前折好，否则长句直接冲出画面。
    光按「每 9 字一断」会切断词（`为什么能打动这么多|妈妈`），要按 `|` 分段后再做一次
    「均衡 + 不切开带色关键词」的小 DP。

22. **字幕贴片的高度要按「ascent → 字身下沿」实测，不能按 1.05em 估。**
    Pillow 的 `anchor="la"` 把 y 钉在**字体 ascent** 上，而 CJK 字体的 ascent 比汉字墨迹顶
    还高一截（Noto Sans CJK 实测 ≈0.14em），汉字墨迹底又在基线下 ≈0.28em —— 于是
    「ascent 顶 → 墨迹底(含描边)」≈**1.34em**，比 `LINE_PITCH`(1.30em) 还大。
    `caption_layer` 原来把贴片开成 `size*1.05 + pad*2`、整块开成 `lh * 行数`，
    两条都比实际需要矮：每行字幕的下沿被画布底边**横着削平**，双行字幕的第一行尤其明显
    （早期样片的 `output/final-*.mp4` 里就能看到）。
    现在 `_render_line` 用 `DESCENT_EM = 1.34`，`_render_block` 用
    `lh*(n-1) + max(piece.height)`（不是 `lh*n`）。改字号/字体后仍要抽帧复核 ——
    换一款 descent 更大的字，1.34 也得跟着量。

23. **loudnorm 的单遍模式不保证真峰，后面必须补一级 `alimiter`。**
    它内部的限制器按**采样**峰值工作，而 `verify.py` 卡的是 `loudnorm` 量出来的
    **真峰**（inter-sample）。低频撞击（`impact-bass-2` 那类）实测能冲出 +2dB：
    采样峰 −3.6dBFS 时真峰是 −1.6dBTP，`true-peak` 一项必红，而且
    **调小 `audio.sfx_volume` 几乎没用** —— loudnorm 是自适应的，把音效压 4dB，
    它就把整体增益抬回来 4dB（实测只降了 0.4dB）。加 `alimiter` 之后同样参数下
    真峰 −2.95dBTP，稳过。三个要点：
    - 阈值留余量：`limit = 10^((TP − 1.4)/20)`（TP −2.6 → 0.63），不能直接取 TP；
    - **必须带 `level=disabled`**，否则它做补偿增益，安静段会被整体抬起来；
    - 限制器放在 loudnorm **之后**。放前面的话 loudnorm 会把削掉的量再加回去。
    代价是整体响度掉 ~0.35dB（−14.8 → −15.2 LUFS），在 ±1.5 容差里。

24. **旁白 / BGM 的音量别靠耳朵定，按「空隙段 vs 说话段」分别量 RMS。**
    混完一条片子觉得「有 BGM 了」，很可能其实没有：第一次给一条 58s Vlog 铺床垫，
    `bgm_volume=0.32` 配 `duck{threshold:0.05, ratio:5}`，量出来**说话段只比无 BGM 高 0.2dB**
    —— 等于只在句间缝隙里露了个头。三个数要一起看：
    - 量法：从 `work/voice-report.json` 取每句的 `[start,end]`，相邻句之间 ≥2.5s 的窗口
      就是「空隙段」，句子本身是「说话段」，各自拼起来算 RMS。
    - **闪避不能下狠手。** 5:1~6:1 的 ratio 会把床垫在说话时压到听不见，而旁白占 44% 时间，
      结果就是整条片子几乎没音乐。`ratio: 3` 足够让人声站住，床垫还留着。
      `threshold` 是线性值：0.05 ≈ −26dBFS（太灵敏，气口也触发），0.08 ≈ −22dBFS 更稳。
    - 定档看的是 **「床垫在人声下多少 dB」**，不是绝对电平（loudnorm 在后面会把整体拉平）。
      实测：0.25 → 床垫在人声下 ~17dB（几乎听不见）、0.32 → 13dB、
      **0.55 → 7.4dB（采用，空隙听得很清楚，说话时让位）**、0.90 → 3.8dB（抢话）。
    - 现场声（`voice_volume`）要跟着让：床垫一响，房间噪声就不再是「底」而是「脏」。
      实测从 1.0 压到 0.65 刚好。核验：空隙段频谱重心 1210Hz（音乐+环境）、
      说话段 2688Hz（人声），两层分得开就对了。

25. **字体匹配不能只看文件名，中文族名必须从 name 表里读出来。**
    「换了字体没反应」的根因是 `_font_key()` 只留 `[a-z0-9]`：`阿里妈妈数黑体`、
    `优设标题黑`、`得意黑` 全被归一化成**空串**，而空串是所有名字的子串（老代码专门
    挡了这一点）→ `match_font` 返回 None → `find_font` **静默回落到 Noto**。
    用户把 ttf 丢进 `fonts/`、把中文族名写进 config，渲出来一模一样，还查不出原因。
    实测当时四条冤枉路：`阿里妈妈数黑体`、`优设标题黑`、`得意黑`（没放进来）、
    `不存在的字体` —— **全都静默变成 NotoSansCJKsc-Black**，一个字都不报。

    修法三条，缺一不可：
    - **读字体自称的名字**：PIL 的 `getname()` 给英文族名/字重，中文名只在 name 表里
      （阿里妈妈数黑体在 nameID **16**，优设标题黑在 nameID **1**），自己解 name 表
      几十行就够，不用 fontTools。platform 0/3 是 UTF-16BE，platform 1 的中文记录是 **GBK**
      （先试 GBK 再 latin-1，ASCII 是 GBK 子集所以不会误伤英文名）。
    - **两趟匹配**：先按文件名（不读文件，0.03s，兼容 `AlimamaShuHeiTi` 这类老写法），
      失手了才建 name 表索引（工程目录 0.01s，全系统扫描 ~2s，只在报错路径上付）。
      `_name_key` 保留中文，只去空格和分隔符。
    - **找不到就报错**，并列出**带汉字的**可用族名 —— 系统里几百个 Latin 字体
      （`.SF Numeric`、`Apple Braille`）混进建议列表只会把有用的淹掉。

    另外两处一并修了：`extra_font_dirs` 原来把 `KOUBO_FONT_DIRS`（旧名 `THSP_FONT_DIRS`）排在工程 `fonts/` **前面**，
    和文档写的相反（工程字体该压过系统同族）；ASS 的 `Fontname` 原来直接写 config 里的
    文件名关键词，libass 拿它去 fontsdir 查的是**族名**，一个都认不出来 —— 现在走
    `font_display_name(find_font(...))`。核验方式是**差分**：同一串字在三个字体下
    字身宽 786 / 788 / 746 px、墨迹量 6674k / 6293k / 5029k，两两不同才算真换上了。
    选字体的入口是 `python3 scripts/list_fonts.py PROJECT_DIR`。

26. **质检要三态：`pass` / `fail` / `unchecked`。缺席不是通过。**
    `verify.py` 原来是二态，而且是「跑到哪项写哪项」—— 片子没有、config 没写 duration、
    loudnorm 吐不出 JSON、卡段没启用、草稿没建出来，这些情况下**对应的检查项直接从报告里
    消失**。消失的项没人会去数，于是读报告的人默认「没报错 = 没问题」。
    现在每一项**必被 `add` 一次**，判不了就传 `None`，落成 `unchecked` 并写清为什么；
    报表分别打 pass / fail / 没查 三个数，末尾补一句「有 N 项没查，**不等于通过**」。
    反面同样要守：**「不可判」也不能说成「有问题」** ——那会让人去修一个可能不存在的毛病。

27. **一条规矩只能有一个正本，副本一律写成「见正本 X」。**
    实测抓到一次真漂移：`verify.py` 自己抄了一份标点表（20 个字符），而正本
    `_common.PUNCT_CHARS` 是 43 个 —— ASCII 的 `! " ' ( ) , - . : ; < > ? [ ] ~`
    和一批中英引号**不在检查面里**，所以「标点检查通过」并不等于真的没标点。
    改成 `PUNCT = PUNCT_CHARS`（直接 import）之后，扩到 43 个字符**当场抓出一个假阳性**：
    `[[消杀]]` 的方括号被当成标点了 —— 因为检查前没先脱掉标记语法。
    两件事一起说明：副本会漂，**而检查面和被检查的东西也必须对齐**（脱标记再扫）。
    登记表在 [registry.md](registry.md)，里面还记着 gtrk 的两条写法纪律：
    「引用不复制」（搬过来就会长出会漂的副本）、
    「异源要硬失败不要静默择一」（静默择一 = 没人知道用的是哪份）。


28. **外录对轨：lag 轴取错会把符号整个翻过来，而且「看起来很像对」。**
    双轨收音（相机内录 + 领夹麦外录）换轨前必须测偏移。FFT 互相关
    `irfft(FFT(a)·conj(FFT(b)))[k] = Σ a[n]·b[n−k]` 里，**k = 0..len(b)−1 是正 lag，
    负 lag 在数组末尾**（`nfft−len(a)+1 .. nfft−1`）。第一版在**开头**取
    `c[len(b)−1::-1]` 当负 lag —— 那是正 lag 的倒序，于是实测真值 −0.400s 被报成 **+0.403s**：
    量级分毫不差、方向完全相反，而峰旁比也被搅成噪声（12.1 → 7.4）。
    这种错最危险的地方是**它不会报错**，还会看起来很专业。防线是**造真值样本**：
    合成一对已知偏移的素材（视频前置静音 N 秒 ⇒ offset = N），跑一遍对答案。
    实测四组（+1.5 / −2.0 / +2.0 / 0）全部 **0ms 误差**。

    另外三条同样是踩出来的：
    - **内录和外录音色差很远**（近讲 vs 远场），直接相关原始波形不稳。
      先压成 **50Hz 能量包络**再相关（对音色不敏感、对「同时响同时静」敏感），
      再用原始波形在峰值附近 ±40ms 精修到 1/16 ms。峰旁比的底噪取旁瓣**中位数**
      而不是 RMS —— 旁瓣里有真相关带来的起伏，RMS 会被它抬起来。
    - **`offset` 的语义要一次说死**：*把外录音轨摆在视频时间轴上的起点*。
      正 = 外录晚开（延后 + 补静音），负 = 外录早开（前面裁掉）。
      这轮里我自己按这个语义核对时写反过两次期望值 —— 定义含糊比实现错误更费时间。
    - **低置信不硬上**：产一份剪映对齐草稿（画面 + 外录两条轨）让用户在时间线上拖，
      保存后 `--resume` 读回。有波形有预览，比任何抽听都直观，而且复用了本仓
      已有的草稿能力。**「没换」要在报告里如实登记**，不能被读成「换好了」。

29. **单轨是默认，双轨是加法 —— 别让加法改变默认路径。**
    外录支持做成了「配了 `input.audio` 才动作」：没配时 `align` 步骤打一句
    「没配外录 → 走单轨」就退出，整条链路与改动前逐字一致。换轨产物用
    `work/align-report.json` **查表**接入（`resolve_video` / `merge_cut` 各查一次），
    而不是去改 `config.json` —— 原始素材永远留着，换轨只是「这一轮用哪个」。
    这样重跑幂等，也不会因为一次换轨把工程指向一个删了就没了的产物。

30. **三家分工不是设计出来的，是测出来的：jy1 写内容 / 本项目补样式 / capcut-cli 补交付。**
    为了决定「剪映草稿操作核心用哪个」，把 pyJianYingDraft（jy1）产的草稿真的装进
    剪映 11.5 打开、播放、**保存**，然后逐键对比它保存前后的差异：

    - **顶层键 28 → 28，剪映一个都没加。** jy1 的 schema 是**原生完整**的；
      对比之下 capcut-cli 只写 9 个键（剪映宽容接受、也不补）。转场/文字/动画/
      淡入淡出/轨道段数**全部原样保留**。⇒ 内容层可以放心交给 jy1。
    - **剪映保存后 `draft_info.json` 与 `draft_meta_info.json` 变成密文**（21/24 个草稿如此），
      而 `draft_content.json` **一直是明文**。⇒ 它是第三方唯一能可靠读回的文件，
      必须一直写、且索引要指向它（`root_meta_info.json` 的 `draft_json_file`：24 条指向
      `draft_info.json`，唯一指向 `draft_content.json` 的那条就是 capcut-cli 建的 —— 剪映照样打开）。
    - **关键词变色不需要 fork jy1。** 它的 `styles` 只发一条 `range=[0,len]`，而剪映要的是
      分段。实测参考稿的字段名与 jy1 的**完全一致**（只多一个 `strokes`），所以约 40 行
      后处理把区间切开就行。本项目复用它自己的 `[[ ]]`/`(( ))` 解析器，
      产出与 capcut-cli 的 `text-ranges` **逐字节一致**（24/24 条 range 与颜色全同）。
    - **交付层必须由 capcut-cli 补。** jy1 不注册草稿箱（全库零引用 `root_meta_info.json`）、
      不 staging 素材（绝对路径）、不写 `local_material_id`。capcut-cli 的 lint 会把这四条
      点名，并给出修法：`register --materials --apply` + `lint --fix` —— 补完从
      「4 warning 6 info」变成 **OK 零问题**。其中 `media-outside-draft` 那条还直接引用了
      jy1 自己的 issue #198（`~/Documents` 是 macOS 权限保护目录，剪映可能报「无访问权限」）。

    ⇒ 判据不是「哪个库更强」，而是**「哪一层缺什么」**。见 `scripts/jy_hybrid.py`。

31. **「装进草稿箱」要照抄一条剪映接受过的条目，不能自己拼字段。**
    `root_meta_info.json` 的 `all_draft_store[]` 每条 **38 个字段**（cloud_* / pippit_* /
    tm_draft_* 一大堆），自己拼必然缺项。做法是 `sample = 索引里第一条有条目形状的`，
    `entry = dict(sample)` 再覆盖 8 个与本草稿相关的键。另：`draft_ids` 是**整数计数器**，
    不是 id 列表 —— 往里塞 uuid 会直接 `TypeError`（我踩了）。

32. **实测常量要有保质期：`references/measured.json` + 两个工具。**
    这套 skill 的立身之本就是「先量再抄」，但量完的数字冻在那儿：
    `margin_v: 560`、`outline: 4`、`#F0E098`、`DESCENT_EM: 1.34` —— **没有一个知道是什么时候量的、
    对着什么量的**。它们的出处散在早期工程的 README 和一个代码注释里，
    也就是**skill 级的知识被困在了工程里**。

    现在每条记「值 / 量于何时 / 拿什么量的 / 怎么量的 / 什么时候该重量」，配两个工具：

    - `check_measured.py` —— 校验 `home` 指向的值还和登记表一致（**防漂移**）
    - `recalibrate.py REF.mp4` —— 拿参考片重量一遍，能自动量的当场对答案，
      **量不了的明确列出来**（当前 17 条里只有 3 条能自动量：字幕墨迹底 + 两个强调色）

    顺带修正一个一直用错的量法：`analyze_reference.py` 的 `caption_band.y_bottom_norm`
    走的是**亮带检测**，会被画面底部的大片亮区带跑（实测给 0.9873，那样反推 margin_v 只有 24）。
    真正该量的是**字幕墨迹下沿**，判据是「同一行里同时有很亮的字和很暗的描边」——
    重量得到 0.702H，与当初记的 0.71H 差 1%。

33. **「防漂移」的工具自己会假阴性：`import` 走 `__pycache__`，而缓存按 (mtime 秒, 文件大小) 判有效。**
    写 `check_measured.py` 时第一版用 `importlib.import_module` 读常量。负向测试时把
    `DESCENT_EM = 1.34` 改成 `1.10` —— **尺寸相同**，而用 `cp` 还原后 mtime 与上次编译
    **落在同一秒**，于是 `.pyc` 被判为有效，校验器**读到旧值报 ok**。

    一个专门抓漂移的工具，在值真的变了的时候说「没问题」——这是**最坏的失败方向**。
    同类工具都该引以为戒。修法是 **AST 解析源码取字面量，不 import**：
    不碰缓存、不执行模块、没有 import 副作用，顺带能读到「模块顶层但不是常量」的东西。

34. **报红要报在「保护失效」上，不要报在「现象存在」上。**
    `jianying-drift` 这一项第一版写成「`draft_info.json` 比 `draft_content.json` 新就报红」，
    结果两个工程**全红**——因为你在剪映里打开过草稿，它就会保存。这条会**永远红**，
    于是人学会忽略它，检查项等于没有（「狼来了」）。

    现象（剪映动过）**不是缺陷**；真正的风险是**覆盖保护认不认得出**。
    改成：认得出来 → 绿（附一句「重跑会拒绝覆盖」）；认不出来 → 红（「重跑会静默吃掉剪映的改动」）。
    实测两个工程都绿，而人造的「无 `Timelines/` + 明文 meta」样本正确报红。
