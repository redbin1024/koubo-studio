# 草稿优先：为什么主交付是剪映草稿

口播工坊现在把**剪映草稿**当作主交付，mp4 只作为预览 / 快速发布副本。

原因很直接：mp4 是压平的像素，改一个字就要重跑整条流水线；剪映草稿里每一条轨道、
每一个镜头、每一句字幕都是可继续操作的对象。真正要加转场、做关键帧、换滤镜、
调蒙版、改字幕动画、单独修某一镜头时，必须回到剪映。

## 草稿里有什么

```text
video  主轨      按镜头切段，一段一个镜头（自动模式通常 8–15 段）
video  包装层    卡段 / 结尾发光字 / 收尾淡黑（本次启用的部分）
audio  人声      粗剪原声，独立音量轨
audio  音效      work/sfx-track.wav
audio  旁白      work/voice.wav（存在才上轨）
audio  BGM       work/bgm.wav，带淡入淡出
text   字幕      真字幕对象，关键词上色 + 逐条入场动画；行距由 jianying.line_spacing 控制
video  贴纸      全画布透明 PNG 贴纸，独立轨，只在草稿里
effect 特效      剪映原生特效（如光晕），只在草稿里
filter 滤镜      剪映原生滤镜（如暖食），只在草稿里
```

剪映原生转场挂在主轨切点 segment 上，不单独占一条轨。

主轨**不再是一整条压平视频**：每个镜头是独立 segment。你可以在剪映里：

- 逐镜头 trim、删除、拖动排序
- 在切点加转场（叠化 / 闪白 / 运镜等）
- 给单个镜头加滤镜、特效、关键帧、蒙版、背景模糊
- 单独调某个镜头的人声 / 音效 / BGM 音量
- 直接改字幕文字、颜色、位置、动画
- 重新导出，不受 ffmpeg 渲染管线限制

## 仍然“烘”在画面里的东西

草稿主轨引用的是 `work/graded.mp4`，所以以下内容已经是像素，不再是剪映对象：

- 调色（`grade`）和画面缩放 / 裁切
- 卡段、插图、画中画、发光大字（如果启用）
- 主轨每个镜头的画面本身

这意味着：

- 主轨 segment 可以**剪短**、删除、排序，但不能把某个镜头**延长**到原粗剪之外。
- 要改卡片 / 插图 / 画中画，改 `config.json` 重跑，或在剪映里手工覆盖。
- 要延长镜头，需要回到原始素材手工替换 segment；自动模式暂不直接挂原始片段。

这样做是有意的取舍：先保证草稿**能逐镜头剪、能加剪映效果、能继续交付**，
而不是假装主轨已经是一条完全可回溯到原素材的 NLE 工程。

## 推荐用法

```bash
# 自动出一版可编辑草稿 + mp4 预览
koubo auto my-video --video ~/Movies/口播.mp4

# 打开剪映 → 草稿箱 → my-video
# 在剪映里加转场 / 滤镜 / 关键帧 / 改字幕，导出最终片
```

自动模式仍然会跑三态质检；mp4 预览用于快速看节奏和听感，**最终交付以剪映导出为准**。

字幕在剪映里容易“两行叠在一起”，原因是 `import-srt` 默认 `line_spacing=0.02`；
现在装配完会写 `0.22`（项目内和草稿箱两份都写）。插图卡标题/正文的间距也从
`1.28×` 提到 `1.58×`，不再挤在一起。

## 边界

- 主轨逐镜头是“在压平成片上切段”，不是原始素材时间线。
- 自动模式默认不启用卡片 / 画中画 / 插图 / 剪映原生特效，避免依赖本机未安装的资源。
- 剪映自己打开过的同名草稿默认不覆盖；要保留手改就换 `--name`，确认丢弃才加 `--force-install`。
