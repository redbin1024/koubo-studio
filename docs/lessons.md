# 经验沉淀日志

每轮只记：会重复踩的坑、改变了后续做法的判断、明确未覆盖的轴。

## 第 1 轮 · 2026-10-19 · 草稿优先与验证补课

**背景**：把工作流从“mp4 全自动”转向“剪映草稿主交付”，连续遇到四个“日志正常、草稿错误”的问题。

| 问题 | 根因 | 证据 | 修法 | 未覆盖 |
| --- | --- | --- | --- | --- |
| 草稿没人声 | AAC 抽出的 WAV 42.869s，`add-audio` 请求 42.900s 被拒；`check=False` 静默吞错 | 草稿只有 BGM/音效，日志却打印“人声” | 按源时长钳制 + 强制检查 | 未逐个听审所有音轨 |
| 字幕叠字 | `import-srt` 默认 `line_spacing=0.02` | 剪映 text material 实测 0.02 | 装配后写 0.22（项目内+草稿箱） | 还未在剪映逐帧目视 0.22 |
| 卡片关不掉 PiP | `compose_card` 没判断 `pip.enabled` | 关闭开关后卡片仍有 PiP | 加开关判断 | 其他卡片版式未逐项验证 |
| 主轨退回一整段 | plan 42.761s vs 成片 42.900s，旧逻辑要求差 <0.05s | 草稿主轨 1 段 | 帧对齐 + 差额补到最后一段 | VFR 素材未系统覆盖 |
| 滤镜/特效/贴纸“看起来没用” | API 接受资源名 ≠ 剪映里视觉正确；没有目视证据 | 草稿有 filter/effect 轨，但未打开确认 | 建 L3/L4 登记，要求草稿目视 | 暖食/光晕/叠化仍待确认 |

### 方法层结论

1. **证据覆盖 < 结论范围**：QC 只查 mp4 元数据，不能推出草稿正确；新增 `draft_audit`。
2. **执行层不能自证**：`draft-spec.json` 先落盘，`draft-qc.json` 再对账；不是从产物反推规格。
3. **验证器必须正例+反例**：`tests/test_draft_audit.py` 同时覆盖“好人声/行距”和“缺人声/0.02 行距”。
4. **API 接受 ≠ 效果正确**：原生资源标 L3，必须打开剪映确认后才升级 L1。
5. **风格不能凭空写**：滤镜/鼓点/节奏不搭，根因是默认值不是从用户成片归纳；建空风格模板，等真实参考片。

## 第 2 轮 · 2026-10-19 · 吸收包装层合同/视觉审查

**来源**：auto-edit-pro 的四道门禁、visual-contract、72% 静帧 + 完整 beat 审查；只取方法，不复制代码/素材。

| 问题 | 做法 | 未覆盖 |
| --- | --- | --- |
| 只有对象审计，不能证明画面成立 | 新增 `work/visual-contract.json`：每个包装 beat 写结构/可见区/阅读窗/证据边界 | 语义结构分类仍是手配，不是从 SRT 自动分类 |
| 风格/滤镜/贴纸“写进草稿”不等于“看起来对” | 新增 `visual-review` 包：72% 静帧 + 完整 beat 片段 + 联系表；原生/草稿专属标 requires-capcut-export | 需要人工观看；当前 pending |
| 源片已有烧录字幕会重复 | 新增 `captions.mode`：generated / burned-in / none；source 模式写空 SRT，不叠加 | 没有 OCR 自动检测源片字幕，仍需人确认 |
| 事实边界 | visual-contract 增加 `claim_status`；sourced 必须有 evidence_refs | 没有接入外部事实核验 |

### 结论

包装层也要“先合同、后画面、再人工审”。自动化能保证对象在、时间对、字幕不重复；
**不能保证审美和事实正确**，后者必须留 pending/人工。

## 第 3 轮 · 2026-10-19 · 固定风格与单处字幕

**来源**：talking-head-motion 的 style-lock、固定风格目录、单处底部字幕规则。

| 问题 | 做法 | 未覆盖 |
| --- | --- | --- |
| 风格参数会漂移，无法复现 | `KB-TH-01` 目录/配方 + `style-lock.json`；config 风格投影不一致即红 | 只有一款真实风格；没有 30 款对照 |
| 插图像第二套字幕 | `caption-role` 比对卡片/插图/品牌字与当前 caption；重复/同义记 warning | 文本相似度不是语义理解；5 处仍需人工改标签/删除 |

### 结论

风格要像软件版本一样锁定；字幕只保留底部一处。**发现 warning 不是通过，是把问题摆出来。**
